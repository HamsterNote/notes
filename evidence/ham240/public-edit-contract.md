# Public edit contract follow-up

The published `@hamster-note/notes@3.4.0` includes upload and resolver contracts, but does not include the controller methods introduced here. This source change has not been published. WebBase must consume a new official release before claiming end-to-end restoration or host-owned history works. Do not substitute a local tarball or patch installed output for that acceptance.

`replacePictureReferences({ expectedSessionId, replacements })` checks the live session, input permissions, unique picture `nodeId`, and exact `expectedSrc` for the whole batch before dispatch. Targets must be managed image paths. The complete candidate transaction document must pass strict `encodeHnn` validation before any live dispatch or history boundary. Individually legal replacements can exceed the shell budget together; rejection preserves both views' EditorState (including selection/history), public dirty/encoding state and all observers. Successful changes form one separately undoable transaction shared by the Provider's views. It neither uploads nor deletes files. Missing bytes and failed persistence remain the host's responsibility.

`applyHostDocument({ expectedSessionId, document })` validates the closed HNN codec and applies the smallest changed range without a local history entry or `onChange` echo. It preserves the Provider session and maps view-local state through the transaction. Accepted remote changes can update a document while a picture dialog owns a target; confirmation still checks that target's node identity. Frozen or unrelated draft sessions reject the operation.

`onHistoryRequest(direction, identity)` routes toolbar commands and shortcuts to a host-owned shared history. When present, it owns the command entirely; the library does not silently fall back to per-iframe history. The host must serialize commands, check revisions, and send the resulting canonical document back via `applyHostDocument`. Hosts that omit it retain the existing Provider-owned history.

The methods are optional in the structural TypeScript interface for older host adapters. New controllers created by this source always expose them. WebBase must detect absence and report unsupported recovery before writing any files.

Initial source verification, before the independent-Provider and budget follow-ups: `yarn typecheck`, `yarn test --maxWorkers=2` (55 files / 1095 tests), and `yarn build`. Full output is attached to the round-four HAM-240 delivery; subsequent exact command counts and any timeout retries are recorded separately in each round's evidence.

Budget regression follow-up: `pictureReferenceBudget.test.ts` uses the real DocumentSession and codec. Before the fix both over-budget cases incorrectly returned applied (2 failures / 2 passes); with the fix, exact-limit rejection and cumulative-batch rejection preserve live state and notifications, while each replacement alone produces a valid, saveable, undoable 512 KiB document. The existing codec boundary tests remain unchanged. Round-six command output is delivered on HAM-240.
